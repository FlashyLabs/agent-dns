# Code of conduct

This is a small specification repository. The standard of conduct is the one a careful engineer would expect in any technical discussion.

## Expected

- Argue about the specification, the vectors and the code, not about the person who wrote them.
- Say what you measured and how. A claim about what a resolver does comes with the vector or the command that shows it.
- Report what happened, including when it is worse than expected. A bug found is a contribution; a bug hidden is not.
- Assume the other person read the spec and disagrees for a reason. Ask for the reason.
- Keep private things private: security reports go to `SECURITY.md`'s channel, never to a public thread.

## Not accepted

- Harassment, personal attacks, or discriminatory language of any kind.
- Publishing someone else's private information.
- Using a real third party's domain as the subject of a demonstration, exploit or example without their consent. Vectors use `example.com`, `example.net` and `org/example`; discussions should too.
- Sustained disruption of a discussion after a maintainer has asked for it to stop.

## Enforcement

Maintainers may edit, remove or lock contributions that break this standard, and may decline further contributions from someone who repeatedly does. Concerns about conduct, including about a maintainer, can be raised privately at the address in `SECURITY.md`, which is the one private channel this repository has; the note there about confirming the address applies.

This document applies to every space the repository owns: issues, pull requests, discussions and commit messages.
